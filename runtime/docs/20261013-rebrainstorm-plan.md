# Rebrainstorm after a no-viable candidate slate

## User Prompts, Verbatim

```text
if no_viable_candidate, then the outer loop should re-brainstorm, right?
```

```text
fix the issue then continue.
```

Runtime0.5.2 changes a first no-viable inventory into`rebrainstorm_required`.
Rebrainstorming requires evidence-backed authority, infrastructure, evidence,
objective, budget or external-coordination change; it cannot repeat the same slate
under new names. A selected newly viable candidate binds the next proposal. If no
candidate survives, the runtime enters`awaiting_context_change` with explicit
unblock conditions rather than pretending the research goal is complete.
